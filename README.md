# Quant

个人量化交易研究仓库。围绕策略的开发、回测与评价，把可读、可复用的代码沉淀到各目录中。

## 目录结构

| 目录 | 说明 |
| --- | --- |
| [app/](app/) | 界面层：本地网页表单，输入代码、区间与策略后生成并弹窗展示回测报告；内含 macOS 与 Windows 两个双击启动器。 |
| [backtest/](backtest/) | 回测层：把每日仓位变成净值曲线——T 日收盘信号、T+1 日开盘按市价成交，按换手收取手续费；价格用前复权口径（已含分红再投资）。 |
| [data/](data/) | 回测数据。[data/backtest/a_share/](data/backtest/a_share/) 为 A 股 2006–2025 全市场日线固定快照（含退市股、7 只基准指数，无幸存者偏差），详见其 [README](data/backtest/a_share/README.md)。 |
| [factor/](factor/) | 因子层：纯因子计算函数，输入价格序列、输出因子序列，不含交易观点。 |
| [scripts/](scripts/) | 数据查询与策略评价工具：[query_a_share.py](scripts/query_a_share.py) 按代码与时间区间读取日线；[evaluate_strategy.py](scripts/evaluate_strategy.py) 输入日收益率序列计算年化夏普、Deflated Sharpe（Bailey & López de Prado, 2014）、最大回撤、最长回撤时间；[test_strategy.py](scripts/test_strategy.py) 用截断法检测前视偏差。 |
| [strategy/](strategy/) | 策略层：消费因子生成信号与每日目标仓位，信号滞后一日生效。每个策略单独一个子文件夹，内含策略代码与回测报告。 |

### 回测链路

各层单向依赖，一份策略从数据到绩效的完整流程：

```
数据层：日线行情（date, open/high/low/close, pctChg, ...，前复权，含分红再投资）
        ↓
因子层：由价格序列计算因子，只算数，不含交易观点
        ↓
策略层：信号 → 每日目标仓位（0/1，信号滞后一日生效）
        ↓
回测层：T+1 开盘市价成交，按换手扣手续费，输出逐日净值
        ↓
评价层：Sharpe / DSR / 最大回撤 / 回撤持续时间
```

> `.claude/` 为 Claude Code 的本地配置与技能，不属于策略代码。

## 本地运行

1. 安装 **Python 3.10+**（Windows 安装时勾选 *Add python.exe to PATH*）；
2. clone 仓库后，在仓库根目录安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

3. 行情数据（两个 parquet 文件）不随 git 分发，需手动拷贝到：

   ```
   data/backtest/a_share/daily_stocks.parquet
   data/backtest/a_share/daily_indices.parquet
   ```

4. 双击启动器：macOS 用 [app/启动回测-macOS.command](app/启动回测-macOS.command)（首次双击被拦截时，右键 → 打开），Windows 用 [app/启动回测-Windows.bat](app/启动回测-Windows.bat)；浏览器会自动打开页面。启动器会自检数据与依赖，缺失时给出提示。

## 要点

**1. 交易成本（Transaction costs）**

不含交易成本的回测表现没有任何参考价值——一个扣费前 Sharpe 很高的策略，扣费后可能直接亏损。回测时至少要计入两部分：

- **手续费（commission）**：按每笔交易（单边，买入或卖出，不是一个来回）计，常用假设为 **5 个基点（0.05%）**；
- **滑点（slippage）/ 买卖价差（bid-ask spread）**：用 **0.5 ×（平均 bid-ask 价差）** 估算成交价相对信号价的偏移（即取买卖价差的一半）。

**2. 数据选择**

回测结果只取决于喂进去的数据，选数据时先确认以下几点：

- **数据频率**：频率要与策略的持仓周期匹配，不要拿日频数据去做日内策略，也不要为了"数据多"盲目上高频——只有匹配的频率才是有效样本。
- **复权（拆股与分红）**：除权除息日价格会跳空，未复权会触发错误信号。优先直接用已经拆股/分红复权的数据；自行复权要用**乘子**，对除权日 $T$ 之前的价格乘以下述因子：拆股比例为 $N{:}1$ 时乘子为 $\frac{1}{N}$；每股分红 $d$ 时乘子为 $\frac{\text{close}(T-1) - d}{\text{close}(T-1)}$，多次事件的乘子为各因子之积。乘子法保证调整前后日收益率一致；若改成直接减去 $d$，只能保证价差一致，日收益率会被改变。
- **幸存者偏差（Survivorship bias）**：只含存活至今的标的会系统性高估绩效（书里的例子：一个"买低价股"策略在无幸存者偏差数据上是 −42%，在有幸存者偏差数据上变成 +388%）。免费数据源（如 Yahoo!）通常有幸存者偏差；买不起无偏差数据库就自己每天存全市场的 point-in-time 数据，或尽量用近期数据回测以减少被剔除标的的扭曲。
- **高低价噪声**：日频数据的 high/low 远比 open/close 脏（极小成交、订单路由不同、错误 tick 未过滤），用 high/low 触发的限价单回测会虚高成交率，从而虚高收益；依赖 open/close 的回测更可靠。取数后用日收益率做错误检查：距均值 4 个标准差以上的日子，应有新闻或指数同步异动支撑，否则数据可疑。
- **绩效口径**：跨策略/跨人比较时优先用 Sharpe、最大回撤、MAR ratio，而非 CAGR——后者的分母口径（单边还是双边资金、是否加杠杆、用期初还是日均净值）不统一，容易产生歧义。

**3. 前视偏差（Look-ahead bias）——截断测试**

信号生成时用了当时还不可得的数据（例如用"当日最低价"触发买入、用全样本回归系数生成当日信号）。防范方法是所有信号只用上一期末及之前的数据（对相关序列做 lag）。

最终检查用**截断测试**：

1. 用全部历史数据跑回测，保存每日仓位 → 文件 A；
2. 删掉最近 N 天（N 取 10~100）再跑一次 → 文件 B；
3. 把文件 A 也截掉同样的最近 N 天，使 A、B 末日和长度一致；
4. 比较 A、B 每个交易日的仓位，**必须完全相同**。出现差异就说明程序在第 T−N 天用到了未来数据，必须定位修正。

本仓库 [scripts/test_strategy.py](scripts/test_strategy.py) 已实现该截断测试（`test_lookahead_bias`）。

**4. 数据窥探偏差（Data-snooping bias）——限制参数个数 + DSR**

在同一份数据上反复调参/调定性规则（开盘还是收盘成交、是否隔夜持仓、大盘还是中盘股等），会把噪声当成 Alpha，回测表现虚高。缓解手段：

- **自由参数不超过 5 个**（含进出场阈值、持仓周期、均线回看期等）；更好的做法是在滚动窗口内动态优化参数，或对多组参数取平均，减少对单一最优参数的依赖；
- 用 **Deflated Sharpe Ratio（DSR, Bailey et al., 2014）** 校正"调了这么多次才得到这个 Sharpe"的选择偏差——调整次数越多，真实（预期实盘）Sharpe 相对回测 Sharpe 被压缩得越狠。

本仓库 [scripts/evaluate_strategy.py](scripts/evaluate_strategy.py) 已实现 DSR（`deflated_sharpe`）。

**5. 样本量要与目标 Sharpe 匹配**

回测 Sharpe 只是对"真实 Sharpe"的有限样本估计。Bailey et al. (2012) 给出达到统计置信所需的最少数据（日频，252 天/年）：

| 目标（95% 置信） | 所需回测 Sharpe | 所需样本量 |
| --- | --- | --- |
| 真实 Sharpe ≥ 0 | ≥ 1.0 | 681 天（≈ 2.71 年） |
| 真实 Sharpe ≥ 0 | ≥ 2.0 | 174 天（≈ 0.69 年） |
| 真实 Sharpe ≥ 1 | ≥ 1.5 | 2739 天（≈ **10.87 年**） |

结论：若想有信心地说策略真实 Sharpe 能到 1，回测 Sharpe 至少 1.5 且需要约 10.87 年日频数据。**回测 Sharpe 越高，所需样本越短**。这一标准同样适用于样本外（纸面交易）的长度。

**6. 敏感性分析（Sensitivity analysis）**

在训练集和测试集上都已拿到合理表现后，逐个小幅变动参数或模型的定性设置，观察绩效变化：

- 只要参数偏离最优点一点绩效就剧烈下滑 → 几乎可以确定存在数据窥探偏差（过拟合噪声）；
- 重点尝试**简化模型**：逐个删掉交易条件，看绩效在去掉哪一条时崩塌——如果某个花哨条件是必不可少的，要高度警惕；
- 稳健模型的表现应在最优参数附近的一个参数区间内都"还行"，而不是只在一个尖峰上成立。

**7. 选择零售账户还是自营交易账户（Retail vs. Proprietary）**

独立交易的首要商业决策：开零售经纪账户，还是加入自营交易公司（prop firm）。两者不是非此即彼，可以同时开多个账户（远程加入 prop 通常不强制签竞业协议，只需向 prop 和 FINRA 披露为"外部商业活动"并事先取得许可），用不同账户跑不同策略、对比执行质量。

| 维度 | 零售账户 | 自营交易账户 |
| --- | --- | --- |
| 开户门槛 | 无 | 需通过 FINRA Series 7 考试及其他限制 |
| 初始资金 | 较高 | 较低 |
| 杠杆 | SEC Reg T：隔夜约 2x、日内约 4x | 公司自定，日内/对冲仓位可达 20x 以上 |
| 亏损责任 | 无限责任，除非以 S-Corp/LLC 等实体开户（损失限于初始投入；2015 年瑞郎脱锚后曾有零售客户被追缴负权益） | 限于初始投入 |
| 佣金/费用 | 佣金低（每股可低于 0.5 美分），数据月费少 | 佣金较高，月费明显 |
| 经纪商破产风险 | 无，账户受 SIPC 保险 | 有，账户不受保，需查公司资产负债表与风控 |
| 培训/指导 | 无 | 可能提供（有时另收费），其交易限制（如禁止仙股、禁止隔夜裸空）本质上也是风控保护 |
| 策略泄露 | 风险低（尤其经纪商无自营部门时） | 有风险，公司可能用自有资金"搭便车"跟单，增加你的市场冲击成本 |
| 交易限制 | SEC 允许范围内无限制 | 可能有持仓风格限制 |
| 风控 | 主要靠自己 | 由公司强制，更全面 |

选定类型后，挑具体机构也不能只看手续费，还要考察：

- **暗池流动性接入（dark-pool access）与执行速度**：手续费只是交易成本的一部分，有时只是小头。大券商先进的执行系统和对暗池（内部撮合网络或 Liquidnet、ITG Posit 等另类交易系统）的高速接入，常常能把成交价改善几美分/股，足以覆盖其更高的佣金。最好同时在多家开户实盘对比实际执行成本。
- **可交易标的范围**：不少券商或自营公司不允许交易期货或外汇，这会限制业务扩展。
- **API**：平台必须提供应用程序接口，让你的程序能接收实时行情、生成并自动报送订单；没有 API，高频量化交易无从谈起。
- **模拟交易账户（paper trading）**：没有它就很难在不冒真金白银风险的情况下测试 API。更理想的是还提供"仿真器"账户（如 IBKR demo），用历史报价回放成"实时"行情，便于随时调试程序。
- **名声与财务实力**：对自营公司尤其关键——自营账户不受 SIPC 保护，公司可能因其他会员的错误交易而倒闭（如 WorldCom、Refco）。要确认其为在交易所注册的经纪商（接受交易所与 SEC 审计），到 FINRA BrokerCheck（brokercheck.finra.org）查看是否有客户投诉、仲裁或监管处罚等"Disclosure"，并参考 elitetrader.com 上在/前会员的评价，确认其赎回资金是否顺畅。
