# 因子编写器：技术因子代码生成

根据用户的自然语言描述，生成符合 pandas/numpy 规范的技术因子代码，并自动生成完整的因子文档。

## 工作流程

1. **理解需求**：仔细阅读用户对因子的描述，确认：
   - 因子计算逻辑是什么
   - 需要哪些参数，默认值是多少
   - 输出单因子还是多个因子

2. **确认数据约定**：**严格遵守以下规则，不得修改或添加额外字段**：
   - 输入数据 `df_data` - pandas DataFrame，**固定只包含以下8个字段**：
     - `date`: 日期
     - `prev_close`: 前收盘价
     - `open`: 开盘价
     - `high`: 最高价
     - `low`: 最低价
     - `close`: 收盘价
     - `volume`: 成交量（股）
     - `value`: 成交额
   - **重要**: 输入数据中不存在 `last_1450`, `vol_share_1500` 等其他字段，**严禁**在代码中引用这些不存在的字段
   - **所有数据已经是每日收盘数据**，直接使用 `close` 作为当日收盘价即可，不需要处理盘中分时数据
   - 使用类封装，数据在 `__init__` 中传入
   - 使用向量化操作避免循环，优先使用 numpy 加速计算
   - 正确处理 nan 值（开头 N-1 个数据）

3. **编写因子代码**：先生成 Python 因子代码：
   - 提供完整可运行的 Python 类
   - 类名根据因子名称命名（如 `RSI`、`BollingerBreadth` 等）
   - `__init__(self, df_data)`: 构造函数接收原始数据
   - `cal_continue(self, params)`: 计算因子函数，`params` 是字典，可传入自定义参数
   - 添加必要的注释说明关键计算步骤
   - 确保代码简洁清晰，符合 PEP8 规范

4. **保存文件**：**必须**为每个因子创建独立子文件夹，所有相关文件都放在该文件夹内：
   - 第一步：先创建文件夹 `factors/{因子名称小写下划线}/`
   - 第二步：保存代码：`factors/{因子名称小写下划线}/{因子名称小写下划线}.py`
   - 如果 `factors/` 目录不存在，先创建它，再创建因子子文件夹
   - **严禁**将所有文件直接放在 `factors/` 根目录下

5. **自动测试**：使用通用测试脚本验证代码可运行，测试完成后自动将因子值保存为CSV文件：
   - CSV：`factors/{因子名称小写下划线}/{因子名称小写下划线}.csv`
   - 日期格式使用 `YYYYMMDD` 整数格式（如 `20140102`）

6. **因子评价**：运行因子评价脚本，评价结果独立保存为 `{因子名称}_evaluation.md`，放在因子文件夹中。

7. **用户确认**：因子评价完成后，**必须暂停并提示用户**：
   - 请用户检查生成的因子代码是否正确
   - 请用户查看因子评价结果是否符合预期
   - 等待用户确认没有问题后，再进行下一步

8. **生成因子文档**：得到用户确认后，生成因子文档，保存为 markdown 文件 `{因子名称小写下划线}/{因子名称小写下划线}.md`，严格遵循以下格式。

## 文档格式

**ALWAYS 使用这个精确格式**：

```markdown
# 因子文档

## 因子名称
{因子名称}

## 因子描述
{这段因子描述了什么，反映了什么市场现象，用来做什么}

## 计算公式
如果因子参考了经典公式并做了修改，**在同一个章节内**同时写出原公式和修改后公式，并说明修改内容：
- 原公式：$ {原始计算公式} $
- 修改后：$ {修改后计算公式} $

如果是全新设计因子，直接写出完整公式：
$ {完整的计算公式} $

**公式风格**：像Alpha101那样简洁表示，复杂函数直接用函数名简写（例如 `correlation(rank(open), rank(volume), 10)`），不需要展开函数定义，保持公式简洁。

其中：
- $ 变量名/函数名 $：变量说明，如果是函数要解释函数的含义（包含参数说明，注明默认值）
- $ 另一个变量/函数名 $：另一个变量说明，函数解释含义

## 因子逻辑与信号
- **市场逻辑**：解释公式各部分背后的设计思路，为什么使用这个指标，这个变换/运算反映了什么市场现象，背后的投资逻辑是什么
- **信号解读**：因子值多大代表什么信号，因子值增大/减小分别对应什么市场预期，应该买入还是卖出，如何根据因子值构建交易策略

## 取值范围
{说明因子的理论取值范围，根据样本统计给出实际统计值：均值、标准差、偏度、一阶自相关性等，说明是否需要标准化处理}
```

**markdown格式强制规范**：必须严格遵守以下规则，否则不规范：
1. **第一行必须是顶级标题** `# 因子文档` - **这是强制要求**，不允许第一行是其他内容
2. **所有标题前后必须有且只有一个空行**（上一个章节结束后空一行，然后标题，标题后再空一行）
3. **所有列表前后必须有且只有一个空行**
4. **禁止文件开头多余空行**，文件第一行必须是 `# 因子文档`，不能是空行
5. **章节顺序必须严格固定**，不允许调换顺序，不允许添加额外章节：
   ```
   # 因子文档
   ↓ 空一行
   ## 因子名称
   ↓ 空一行
   {因子名称，这里只是名称，不要加其他内容}
   ↓ 空一行
   ## 因子描述
   ↓ 空一行
   {因子描述：这段因子描述了什么，反映了什么市场现象，用来做什么}
   ↓ 空一行
   ## 计算公式
   ↓ 空一行
   $ {完整的计算公式} $
   ↓ 空一行
   其中：
   - $ 变量/参数名 $：变量说明，参数注明默认值
   ↓ 空一行
   ## 因子逻辑与信号
   ↓ 空一行
   - **市场逻辑**：解释公式各部分背后的设计思路，为什么使用这个指标，反映了什么市场现象
   - **信号解读**：因子值大小代表什么信号，如何根据因子值进行交易
   ↓ 空一行
   ## 取值范围
   ↓ 空一行
   {说明因子的理论取值范围，根据样本统计给出实际统计值：均值、标准差、偏度、一阶自相关性等，说明是否需要标准化处理}
   ```
6. **不允许添加额外章节**，比如 `使用说明`、`参考文献` 等都不允许出现在因子文档中，保持简洁。所有额外信息应该放在因子评价报告中。
7. **LaTeX公式下划线必须转义**：在LaTeX公式中，所有下划线必须用反斜杠转义，写作 `\_`。例如 `open` 没问题，但 `prev_close` 必须写成 `prev\_close`，否则markdown渲染错误。
8. 使用 `$ ... $` 包裹行内公式，不要使用 `$$ ... $$`（除非是独立公式块）

## 自动测试

生成因子代码保存到用户项目的 `factors/` 目录后，**自动执行测试**：
- 使用技能目录下 `scripts/test_factor.py` 通用测试脚本
- 测试数据固定为技能目录下 `assets/000905_20140102_20250630.csv`（数据区间：2014-01-02 至 2025-06-30）
- **重要：必须根据因子代码中定义的默认参数传入正确的参数JSON**，否则测试会报错
- 执行命令：`python <skill-install-path>/factor-writer/scripts/test_factor.py factors/{因子名称小写下划线}/{因子名称小写下划线} -p '参数JSON'`
- 执行完成后自动打印计算结果，验证代码正确性，并自动保存因子值到CSV文件

**不需要**每个因子都单独写测试用例，使用同一个通用脚本测试即可。

## 因子评价

测试通过后，**自动进行因子评价**：
- 使用技能目录下 `scripts/evaluate_factor.py` 因子评价脚本
- 基于测试数据（2014-01-02 至 2025-06-30）计算因子在**多个预测周期**(1/5/10/20日)的各项评价指标：
  - **IC分析**：整体IC、滚动IC均值、ICIR（信息系数比率）
  - **因子分布统计**：均值、标准差、偏度、峰度、一阶自相关性（衡量因子稳定性）
  - **分层测试**：五分位分组平均收益，汇总多空收益表格+收益单调性检验
- **重要：必须根据因子代码中定义的默认参数传入正确的参数JSON**，否则评价会报错
- 评价结果生成 markdown 格式，**独立保存**为 `{因子名称}_evaluation.md`，放在因子文件夹中

执行命令：`python <skill-install-path>/factor-writer/scripts/evaluate_factor.py factors/{因子名称}/{因子名称} -p '参数JSON'`

`evaluate_factor.py` 脚本会自动生成完整的markdown格式评价报告，包含IC分析、因子分布统计、分层收益测试、策略收益汇总等内容，不需要手写评价格式。

## 注意事项

1. **向量化优先**：**永远**使用 pandas/numpy 向量化操作，**严禁**使用 Python for 循环逐行计算。向量化代码更快更稳定。
2. **处理边界**：正确处理开头的 N-1 个 NaN 值，不要报错
3. **数据字段不变**：只使用约定的8个输入字段，不允许引用不存在的字段
4. **独立文件夹**：每个因子必须有自己的独立子文件夹
5. **命名规范**：因子类名使用大驼峰命名 (如 `RSI`, `BollingerBands`)，文件/列名使用下划线命名法 (snake_case)
6. **可测试**：代码应该是完整可运行的，用户复制粘贴就能用
7. **必须运行测试**：代码保存后必须运行自动测试和因子评价，不可以只生成代码就结束
8. **解释原因**：为什么这样实现？对用户理解因子有帮助的信息都应该写在文档里
